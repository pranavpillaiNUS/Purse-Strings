# Local Web App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `npm run app` serves a local page that starts `demo:flow` with the manager's typed request and replaces each Enter press with a button, showing the company files, a labelled conversation and the ledger.

**Architecture:** A new 127.0.0.1 server spawns one `demo:flow --pause` child per take and writes `\n` to its stdin only when `session.json` says the flow waits for exactly that step. State comes from the existing `dashboard-state.ts` reader plus the take's `request.txt`, `draft.json` and `*.review.json`. The checker, ledger, backend, shopper, contracts and PayPal gateway do not change.

**Tech Stack:** Node 24.15+/26 ESM, erasable TypeScript, `node:http`, `node:child_process`, `zod` (already a dependency), `node:test`. Plain HTML/CSS/JS page; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-10-web-app-design.md`

## Global Constraints

- Serve on `127.0.0.1` only; default port `7171`; `--port` overrides; Host must be `127.0.0.1:<port>` or `localhost:<port>`.
- Every `POST` needs header `X-Splittap-Token` equal to the per-launch token and `Origin` equal to `http://127.0.0.1:<port>` or `http://localhost:<port>`; JSON bodies ≤ 8,192 bytes; unknown fields refused.
- Reuse `SECURITY_HEADERS` from `apps/cli/src/dashboard.ts` on every response.
- One take at a time, each in a new folder `.runtime/app/take-<UTC yyyyMMddTHHmmssZ>`; never reuse or delete a take folder.
- Request text: 1–1,000 characters after trimming; only passed with Claude (`--live`).
- Spawn with `process.execPath` and an argument array, never a shell.
- The app server reads no `.env`; the child inherits the environment exactly as a terminal run would.
- The read-only dashboard, `DASHBOARD_READ_COMMANDS` and their tests stay unchanged.
- Page: no external URLs, system font stack `"Avenir Next", "Segoe UI Variable", system-ui, sans-serif`; tokens Paper `#EEF1F4`, Ink `#1C2633`, Stamp violet `#4B3FA8`, Accepted `#1F7A55`, Refused `#B4372E`, Waiting `#B7791F`; all untrusted text rendered with `textContent`.
- Copy: sentence case; button labels exactly "Start run", "Next scene", "Confirm this mandate", "Buyer has approved", "Stop run", "Open PayPal approval page"; never call a reservation payment or a fake order real; label the scripted stand-in and Claude's words.
- Run `npm test`, `npm run typecheck`, `npm run demo` before each commit that touches code.

## Review Focus

- **Double-clicked Continue** — two clicks while the flow waits once must send one Enter, not confirm and then skip a scene. (Task 3 test `a second continue for the same wait sends nothing`.)
- **Hostile text in the request, Claude's summary or terminal output** (`<img onerror>`, ANSI escapes) — shown literally, never executed or styled. (Task 6 test `hostile text renders as text`; Task 3 strips ANSI.)
- **The child exits on its own** (crash, failure, finish) — the take shows ended with its exit code; Continue and Stop are refused. (Task 3 test `an exited child refuses continue and stop`.)
- **Stop while a command runs** — refused, so a capture is never cut off. (Task 3 test `stop is refused unless the flow waits`.)
- **Paths with spaces and Windows** — the take folder and request file paths go as separate arguments; no shell quoting. (Task 3 test `spawn arguments are an array with the take folder as one element`.)
